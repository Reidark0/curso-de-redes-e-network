# DECISÕES

Registro de decisões tomadas sem consulta (regra 4), divergências entre o prompt e o código real e ajustes de critério.

## Fase 0 (2026-11-04)

- **D01. Branch.** O prompt pede a branch `revisao-curso`. Esta sessão em nuvem foi configurada para desenvolver e fazer push só na branch `claude/focused-pascal-00emu4`, e a configuração proíbe push em outra branch sem permissão explícita. Como é uma branch própria (não a principal), ela cumpre o objetivo da regra 0.0. Todo o trabalho vai para `claude/focused-pascal-00emu4`, sem force push. Quem retomar deve fazer checkout dessa branch (em vez de `revisao-curso`).
- **D02. Fonte da verdade.** Existem fontes em `data/lessons/**` (190 arquivos), `data/modules/` (18) e `data/course-data.js`. No single HTML original, os 190 blocos de aula, os 18 de módulo e o de `course-data.js` são **idênticos** às fontes depois de tirar as linhas `import` e o prefixo `export ` (215 de 227 blocos iguais; os 12 diferentes são JS do app, que não é tocado). Não há script de build no projeto (nenhum package.json, Makefile, build*, *.py, *.mjs). O `build_single` vai usar o single HTML original como molde.
- **D03. Formato de serialização.** As aulas novas são gravadas como `export const lessonXXXX = ` + `JSON.stringify(obj, null, 2)` + `;`. Em 107 originais, alguns blocos aninhados têm outra indentação. O conteúdo é o mesmo e o formato continua JSON válido.
- **D04. Fatos da seção 2 confirmados:** 190 aulas em 18 módulos (m00–m13 com 10, m14 com 14, m15–m17 com 12); ~1,17 milhão de palavras; as 20 chaves de `content` em todas as aulas; `stripOuterLessonSection` remove o primeiro `<section>` e o primeiro `<h2>`; as seções ausentes são omitidas sem quebrar. Bug do quiz confirmado: 26 aulas com `answer` textual (158 questões, todas batem exatamente com uma opção) e 16 com `correctAnswer`/`correctIndex` numéricos (60 questões). Soma de `estimatedStudyTimeMinutes` = 35.120 min (585 h) × soma de `estimatedHours` dos módulos = 1.029 h. 570 flashcards e 466 questões não têm `id`.
- **D05. Classes CSS: divergência com o prompt.** O prompt cita `callout--problem|--warning|--security`, `comparison-table`, `risk-table` e `flow-list` como classes do CSS, mas elas **não existem** em `assets/css` (as aulas originais as usam, e elas ficam sem estilo). O que existe: `callout`, `.callout.warning`, `.callout.security`, `definition-box`, `evidence-box`, `content-card`, `data-table`, `responsive-table`, `code-block`, `command-block`, `lesson-svg` e algumas `svg-*`. Decisão: o markup novo usa só classes estilizadas, e as classes que já existiam na própria aula podem ficar (CRITERIOS 11.4).
- **D06. Ids de quiz e progresso salvo.** O app salva cada resposta com a chave `question.id ?? índice`. Criar `q1…qN` para as 466 questões sem id (regra 7.7) mudaria a chave e apagaria o progresso salvo dos alunos, o que fere a regra inviolável 5. Decisão: a questão sem id recebe `id` = índice original em string ("0", "1"…), que é exatamente a chave já usada. As questões novas recebem `q<N>` inéditos (CRITERIOS 11.5).
- **D07. Campos invisíveis extras.** Além da lista da seção 2, existem ~45 outros campos de topo que o app não exibe nem indexa (ex.: pedagogicalMap em 24 aulas, accessPolicy em 20, trafficCapture em 18, assessmentBlueprint/adaptiveReview em 12…). Eles recebem o mesmo tratamento dos invisíveis (MOVER o que vale, REMOVER o campo). `prerequisites` é metadado e fica (CRITERIOS 11.3).
- **D08. "Prática equivalente".** Nas 39 aulas, o bloco "Prática equivalente — Esta aula não possui laboratório independente…" fica em `content.labIntro`, que já é invisível. Ele sai junto com `labIntro`. O aluno não perde nada: o botão "Marcar laboratório ou Prática equivalente" é do app.
- **D09. `requiredLabs` dos módulos** lista labs que não existem (ex.: m00 exige lab-0.1…lab-0.10, mas só 145 das 190 aulas têm lab). Isso é corrigido na etapa de fim de módulo (9, item 1).
- **D10. Busca × quiz padronizado.** `search.js` indexa o quiz só por `q.q`/`q.opts`/`q.exp`. Depois da padronização para `question/options/explanation` (regra 7.7), o texto do quiz sai do índice de busca, o que é uma perda pequena. Não alteramos o app (regra 2). Fica a recomendação no relatório final de indexar `question/options/explanation`.
- **D11. HTML desbalanceado nos originais:** 14.8 (`securityExample`) e 15.9 (`nextTheme`) têm `</section>` sobrando. Isso é corrigido nas novas versões.
- **D12. Medição (6.2).** As palavras dentro de `<svg>` não contam como teoria (o diagrama já vale 3 min). Teoria visível = chaves exibidas de `content` + campos exibidos de `security`, `troubleshooting` e `glossary`. Lab plausível = `estimatedTimeMinutes` entre 0,5× e 2× de (5 min/passo + leitura do lab a 130 palavras/min).
- **D13. Orquestração.** Cada aula vai para um subagente novo, um por vez, nunca em paralelo, como manda a seção 9. O orquestrador confere arquivos e `validar`, atualiza `PROGRESSO.md` e faz commit + push depois de cada aula.
- **D14. Durações com travessão.** Três aulas (9.8, 9.9 e 9.10) usam "–" em `duration`. As novas versões usam o formato padrão "X-Y min".
- **D15. Linha de base no navegador (single original).** `validar_single.js --browser` sobre `redes_e_network_v2_0_single.html`: sintaxe ok, 190 aulas e 18 módulos, nenhum erro de console, todas as aulas renderizam. Clicar na opção correta da 1ª questão só funciona em 157 aulas: falha em 33 (as 26 de `answer` textual e 7 das 16 com `correctAnswer`/`correctIndex`; nas outras 9, a 1ª questão já usa `a`, mas as demais não). Na 5.2, 5.4 e 5.5, o texto da resposta começa com número e o app usa esse número como índice (ex.: "254…" → opção 254).
- **D16. Módulos em `aulas novas/modules/`.** As cópias mantêm os `import` originais (`../lessons/mXX/…`), como manda "não mexa no resto". Elas servem para o build do single, que remove os imports. Não são um app modular executável a partir de `aulas novas/`.
