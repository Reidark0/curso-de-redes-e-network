Exemplo em DevSecOps

Um runner de pipeline baixa dependências, acessa um registry, envia a imagem para um repositório, aplica manifests no cluster e consulta APIs. O runner é dispositivo final (workload). O proxy corporativo é intermediário. O registry e o API server do cluster são serviços. Firewall, security group, service mesh ou network policy aplicam política.

Quando o pipeline falha com timeout, não conclua de imediato que o código está errado. Pode ser DNS, proxy, rota, firewall, certificado TLS, autenticação, rate limit ou indisponibilidade do serviço externo, e cada hipótese aponta para um papel diferente.
