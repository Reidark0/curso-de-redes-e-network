Funcionamento interno

Acompanhe um notebook (10.10.1.25) abrindo https://intranet.empresa.local, uma aplicação interna. Os endereços são ilustrativos; o que importa é o papel de cada elemento em cada passo.

  1. Cliente inicia: o navegador do notebook (dispositivo final de origem) gera a requisição.
  2. Nome é resolvido: o serviço DNS interno traduz intranet.empresa.local para um IP, por exemplo 10.20.0.15.
  3. Tráfego sai do host: a placa de rede envia sinais pelo meio físico ou sem fio.
  4. Intermediários encaminham: o AP ou o switch comuta os quadros dentro da LAN; o roteador encaminha entre redes; um balanceador pode distribuir a requisição entre servidores.
  5. Políticas são aplicadas: firewalls, ACLs, proxies, security groups ou WAFs permitem, negam ou registram a conexão para a porta 443.
  6. Serviço responde: a aplicação web, hospedada em um servidor, VM ou container (dispositivo final de destino), escuta na porta 443 e processa a solicitação.
  7. Evidências são geradas: logs, tabelas ARP, tabela de conexões, eventos de firewall e métricas registram partes do caminho.

Essa decomposição evita uma armadilha comum: achar que “o servidor está fora” só porque um serviço não responde. O host pode estar vivo e, mesmo assim, o processo estar parado, a porta fechada, a rota errada, o DNS apontar para outro IP ou uma política estar bloqueando.
