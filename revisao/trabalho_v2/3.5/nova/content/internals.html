Funcionamento interno

Quando um host precisa enviar um pacote IPv4, o ARP entra assim:

  1. O host verifica, pela máscara, se o IP de destino está na mesma sub-rede.
  2. Define o próximo salto: o próprio destino (local) ou o gateway (externo).
  3. Consulta o cache ARP para ver se já conhece o MAC desse próximo salto. Se conhece, pula para o passo 6.
  4. Se não conhece, envia um ARP Request em broadcast para ff:ff:ff:ff:ff:ff, que alcança toda a VLAN: "quem tem 192.168.1.1? Responda para 192.168.1.50".
  5. Só o dono daquele IP responde, com um ARP Reply, normalmente em unicast, direto para quem perguntou. O host grava a associação IP-MAC no cache por tempo limitado.
  6. O pacote IP é colocado num frame Ethernet com o MAC resolvido e sai em unicast.

Se ninguém responde ao Request, o host não tem MAC para pôr no frame e o pacote não sai. Os sistemas avisam isso como "host de destino inacessível".

Campos da mensagem ARP

Num frame Ethernet, o ARP é identificado pelo EtherType 0x0806. Request e Reply têm o mesmo formato; os campos que importam numa captura são:

CampoTamanhoFunção
Hardware Type / Protocol Type16 + 16 bitsA tecnologia de enlace (Ethernet) e o protocolo resolvido (IPv4).
Operation16 bits1 = Request, 2 = Reply.
Sender MAC / IP48 + 32 bitsQuem envia a mensagem e a associação IP-MAC que ele anuncia.
Target MAC / IP48 + 32 bitsO IP procurado. No Request, o Target MAC vai zerado (00:00:00:00:00:00), porque é justamente o que se procura.

No Reply, o MAC procurado vem no campo Sender: é a máquina que responde dizendo "esse IP sou eu, e meu MAC é este".

Como ler a tabela ARP

Linux (ip neigh):  192.168.1.1 dev wlan0 lladdr aa:bb:cc:dd:ee:ff REACHABLE
Windows (arp -a):  192.168.1.1           aa-bb-cc-dd-ee-ff     dinâmico

Cada linha associa um IP a um MAC. No Linux, REACHABLE indica entrada confirmada há pouco, STALE indica entrada ainda utilizável mas não confirmada recentemente, e FAILED indica que o host perguntou e ninguém respondeu. No Windows, as entradas aprendidas por ARP aparecem como dinâmicas. A aula 3.6 detalha como esse cache é mantido e como ler entradas problemáticas.
