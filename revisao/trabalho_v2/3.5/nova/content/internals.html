Funcionamento interno

O ARP começa antes da pergunta em broadcast: primeiro o host compara o próprio IP com o IP de destino usando a máscara e decide quem é o próximo salto.

  1. O host precisa enviar tráfego para um IP.
  2. Ele verifica, pela máscara, se o IP está na mesma sub-rede.
  3. Define o próximo salto: o próprio destino (local) ou o gateway (externo).
  4. Consulta o cache ARP para ver se já conhece o MAC daquele próximo salto.
  5. Se não conhece, envia um ARP Request em broadcast para ff:ff:ff:ff:ff:ff, que alcança toda a VLAN.
  6. O dono do IP responde com um ARP Reply, normalmente em unicast, direto para quem perguntou.
  7. O host grava a associação IP-MAC no cache por tempo limitado.
  8. O pacote IP é encapsulado em um frame Ethernet com o MAC resolvido e sai em unicast.

Onde cada etapa pode falhar

EtapaFalha possível
Decidir o próximo saltoMáscara errada faz o host fazer ARP para o alvo errado (um destino remoto tratado como local, ou o contrário).
Consultar o cacheEntrada desatualizada, IP duplicado ou MAC inesperado.
Request em broadcastVLAN errada ou broadcast storm: o dono do IP não recebe a pergunta ou não responde de forma confiável.
ReplyResposta indevida, IP duplicado ou spoofing.
Tráfego unicastMesmo com ARP funcionando, firewall, rota, porta ou aplicação ainda podem falhar.

Campos da mensagem ARP

Num frame Ethernet, o ARP é identificado pelo EtherType 0x0806. Os campos que importam numa captura:

CampoTamanhoFunçãoObservação defensiva
Hardware Type16 bitsTecnologia de enlace (Ethernet).Estável numa LAN Ethernet; valor inesperado sugere captura fora do contexto.
Protocol Type16 bitsProtocolo lógico resolvido (IPv4).Separa ARP de outros protocolos encapsulados.
Operation16 bits1 = Request, 2 = Reply.Volume alto de Replies, ou Replies que ninguém pediu, merece investigação.
Sender MAC / IP48 + 32 bitsQuem anuncia a associação.Pode ser falsificado: não é identidade forte.
Target MAC / IP48 + 32 bitsO IP procurado. No Request, o Target MAC vai zerado, porque é justamente o que se procura.Requests para muitos IPs em sequência indicam varredura ou comportamento anômalo.

Como ler a tabela ARP

Linux:   192.168.1.1 dev wlan0 lladdr aa:bb:cc:dd:ee:ff REACHABLE
Windows: 192.168.1.1           aa-bb-cc-dd-ee-ff     dinâmico

Cada linha associa um IP a um MAC. No Linux (ip neigh), REACHABLE indica entrada confirmada há pouco, STALE indica entrada ainda utilizável mas não confirmada recentemente, e FAILED indica que o host perguntou e ninguém respondeu. No Windows (arp -a), as entradas aprendidas por ARP aparecem como dinâmicas. Uma entrada do gateway com MAC diferente do documentado, ou que muda ao longo do dia, é uma evidência a investigar, não uma conclusão.
