Conceito

ARP é o protocolo usado no IPv4 para descobrir o endereço MAC associado a um endereço IPv4 dentro da rede local. Ele responde a uma única pergunta: "qual MAC devo usar para entregar este frame ao próximo salto?"

O ARP não resolve nomes (isso é DNS), não roteia pacotes (isso é o roteador), não protege a comunicação e não atravessa roteadores: ele fica restrito ao domínio de broadcast, ou seja, à VLAN. Ele também é exclusivo do IPv4; o IPv6 resolve o mesmo problema com outro mecanismo.

A frase "ARP transforma IPv4 em MAC" exige um cuidado: o IP que o ARP resolve é o do próximo salto, que nem sempre é o destino final. O host decide qual é o próximo salto comparando, pela máscara, o próprio IP com o IP de destino:

Host 192.168.1.50/24 quer falar com…Mesma sub-rede?Próximo saltoARP pergunta por
192.168.1.80 (impressora)SimO próprio destinoMAC de 192.168.1.80
203.0.113.10 (site externo)NãoGateway 192.168.1.1MAC de 192.168.1.1, nunca o do site

No segundo caso, o gateway recebe o frame local, remove a Camada 2, analisa o pacote IP e escolhe o próximo salto seguinte. Por isso a sua tabela ARP só mostra vizinhos da sua sub-rede e o gateway, nunca os servidores da internet.

Erros comuns
  • Concluir que o ARP falhou porque o ping não respondeu: o ARP acontece antes do primeiro pacote do ping. Se o gateway aparece na tabela ARP com um MAC, a resolução local funcionou; o gateway pode só estar bloqueando ping.
  • Esperar ver o MAC de um site em arp -a: para destinos de fora, o MAC usado é sempre o do gateway.
