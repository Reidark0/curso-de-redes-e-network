Funcionamento interno

  1. ipconfig /all: lê a configuração das interfaces no Windows: endereço IPv4, máscara, gateway padrão, servidores DNS, DHCP habilitado ou não, servidor DHCP, sufixo DNS e estado da interface.
  2. ping: envia ICMP Echo Request e espera ICMP Echo Reply. Mede o tempo de ida e volta (RTT), mas não testa TCP, UDP, HTTP ou autenticação.
  3. arp -a: mostra a tabela (cache) ARP, com as associações já conhecidas entre IPs da rede local e endereços MAC. Para um destino remoto, o host só precisa do MAC do gateway, por isso o destino remoto não aparece ali.
  4. tracert: envia pacotes com TTL crescente (1, 2, 3…). Cada roteador que decrementa o TTL até zero pode devolver um aviso de TTL expirado, revelando um salto do caminho.
  5. nslookup: consulta um servidor DNS e mostra qual servidor respondeu e os registros retornados (A, AAAA, CNAME ou MX, conforme a consulta).

Como ler os resultados

O que você vêO que indicaPróximo passo
ipconfig com IPv4 169.254.x.x (APIPA)O host não recebeu configuração IPv4 via DHCP.Investigar cabo, Wi‑Fi, VLAN, AP e DHCP antes de DNS ou aplicação.
Gateway padrão vazioSem rota padrão: o host fala com a própria sub-rede, mas não sabe para onde mandar tráfego de outras redes.Revisar DHCP, perfil de rede ou configuração manual.
Servidor DNS desconhecido (não é o corporativo nem o do roteador)Configuração manual, DHCP indevido ou comprometimento.Comparar com o padrão esperado e acionar segurança se não houver explicação.
ping: “Esgotado o tempo limite do pedido”Nenhuma resposta voltou: ICMP filtrado, destino fora ou caminho de volta quebrado.Testar o gateway e outros destinos para isolar o ponto.
ping: “Resposta de <IP>: Host de destino inacessível”O equipamento cujo IP aparece (o próprio host ou um roteador) avisou que não consegue entregar, por exemplo por ARP sem resposta ou falta de rota.Se o IP for o do próprio host, olhar ARP e rede local; se for um roteador, olhar a rota a partir dele.
tracert com * * * em um salto, mas o destino final respondeEsse roteador não responde a TTL expirado ou limita respostas.Não concluir falha; correlacionar com outras evidências.
nslookup com NXDOMAIN (“Non-existent domain”)O servidor DNS respondeu que o nome não existe para ele.Conferir o nome, o servidor consultado e se é um nome interno que exige DNS interno ou VPN (split DNS).
nslookup com timeoutO servidor DNS não respondeu.Testar alcance até o servidor DNS e se o DNS configurado é o esperado.
Atenção: resposta ausente nem sempre significa falha. Firewalls e roteadores podem bloquear ICMP, não responder a TTL expirado, aplicar rate limit ou responder por caminhos diferentes.
