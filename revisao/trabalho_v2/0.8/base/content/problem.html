Problema

Uma comunicação real atravessa muitas responsabilidades ao mesmo tempo. Um simples acesso a https://sistema.empresa.local pode envolver Wi-Fi, switch, VLAN, ARP, IP, roteamento, NAT, firewall, DNS, TCP, TLS, HTTP, cookie, token, sessão, banco de dados e autorização.

Se tudo isso vira "a rede", o diagnóstico fica impreciso. Você troca o DNS quando a falha é TLS, libera o firewall quando a falha é autorização, culpa o usuário quando o problema é rota, ou abre uma porta perigosa quando bastava corrigir um cabeçalho no proxy.

Modelos em camadas existem para dividir essa complexidade em responsabilidades, e é por isso que equipes diferentes conseguem trabalhar em partes diferentes do problema: o fabricante da placa de rede não precisa implementar HTTP, e o desenvolvedor da API não precisa lidar com o sinal elétrico no cabo. Com camadas, cada hipótese é testada no lugar certo e com a evidência adequada.
