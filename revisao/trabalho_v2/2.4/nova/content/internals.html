Funcionamento interno

Campos principais do quadro Ethernet

CampoTamanhoPara que serve
MAC de destino48 bitsIndica o destinatário local do quadro.
MAC de origem48 bitsIndica a interface que enviou o quadro. É por ele que o switch aprende onde cada aparelho está.
EtherType16 bitsIndica o protocolo que vai dentro do quadro: 0x0800 = IPv4, 0x0806 = ARP.
PayloadvariávelCarrega a PDU da camada de cima, por exemplo o pacote IPv4 (aula 2.2).
FCS32 bitsDetecta erro no quadro: o receptor descarta o quadro com FCS inválido e conta um erro CRC (aula 2.3).

Do IP ao quadro entregue

  1. O host compara o IP de destino com o seu IP e máscara: o destino está na rede local ou fora dela?
  2. Se for local, precisa do MAC do destino; se for remoto, do MAC do gateway. Primeiro procura na sua tabela ARP.
  3. Se não conhece o MAC, envia um ARP Request para FF:FF:FF:FF:FF:FF, que alcança toda a VLAN: "quem tem o IP X?".
  4. Só o dono do IP (o destino ou o gateway) responde, com um ARP Reply contendo o seu MAC. O host guarda a associação IP → MAC na tabela ARP.
  5. O host monta o quadro: MAC de destino, MAC de origem, EtherType, payload e FCS.
  6. O switch recebe o quadro e anota na tabela MAC: "este MAC de origem está nesta porta".
  7. Se o MAC de destino está na tabela, o switch envia o quadro só pela porta dele (unicast). Se não está, faz flooding: copia o quadro para todas as outras portas da mesma VLAN, nunca para outras VLANs. Quando o destino responder, o switch aprende onde ele está.
  8. O destino confere o FCS e o MAC de destino e passa o payload para a camada de cima.

Se uma etapa falha, as seguintes nem acontecem. Com a máscara errada, o host faz ARP para um destino que deveria ir ao gateway. Com o host e o gateway em VLANs diferentes, o ARP Request não chega ao gateway e ninguém responde. Nos dois casos, DNS e aplicação podem estar perfeitos e mesmo assim nada funciona.
