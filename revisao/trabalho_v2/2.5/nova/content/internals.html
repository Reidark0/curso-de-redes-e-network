Funcionamento interno

O caminho de um pacote, passo a passo

  1. O host aplica a máscara ao próprio IP e ao IP de destino para saber se o destino está na mesma rede. Falha típica: máscara errada faz o host tratar destino remoto como local, ou local como remoto.
  2. Destino na mesma rede: entrega local, via ARP e Camada 2.
  3. Destino fora da rede: o host consulta as próprias rotas; na maioria dos hosts só existe a default, que envia o pacote ao gateway padrão. Para isso ainda precisa do MAC do gateway, descoberto via ARP. Falha típica: gateway ausente ou errado impede a saída da rede local.
  4. O gateway recebe o quadro, remove o encapsulamento de Camada 2 e analisa o pacote IP.
  5. O roteador consulta a tabela de rotas e escolhe a rota mais específica (maior prefixo) que combina com o destino.
  6. O TTL é decrementado. Se chegar a zero, o pacote é descartado e o roteador pode devolver uma mensagem ICMP Time Exceeded. Falha típica: num loop de roteamento, os pacotes giram entre roteadores até o TTL zerar.
  7. O roteador reencapsula o pacote num novo quadro de Camada 2 para o próximo salto.
  8. O processo se repete até a rede de destino, ou até o descarte por rota ausente, política ou falha. A resposta faz o caminho inverso e precisa de uma rota de retorno.

Ponto-chave: os IPs de origem e destino normalmente permanecem de ponta a ponta, enquanto os MACs mudam a cada enlace. A exceção mais comum é o NAT do roteador de casa, que troca o IP de origem.

Lendo uma tabela de rotas

Exemplo de saída de ip route num host Linux com IP 192.168.1.50/24:

default via 192.168.1.1 dev eth0
10.0.0.0/8 via 192.168.1.254 dev eth0
192.168.1.0/24 dev eth0 proto kernel scope link src 192.168.1.50

A última linha é a rede conectada, que o sistema cria sozinho a partir do IP e da máscara: o que cai nela é entregue direto, sem gateway. Quando várias rotas combinam com o destino, vence a mais específica:

DestinoRotas que combinamEscolhida (mais específica)Resultado
192.168.1.80/24 e default192.168.1.0/24Entrega local (rede conectada)
10.20.30.40/8 e default10.0.0.0/8Envia para 192.168.1.254
8.8.8.8só a default0.0.0.0/0Envia para o gateway 192.168.1.1

No Windows, o equivalente é route print; a default aparece como destino 0.0.0.0 com máscara 0.0.0.0.

Como o traceroute usa o TTL

O traceroute (tracert no Windows) envia sondas com TTL 1, depois 2, depois 3, e assim por diante. Cada roteador em que o TTL chega a zero devolve um ICMP Time Exceeded e, assim, aparece como um salto na lista. Um asterisco significa só que aquele salto não respondeu: ele pode filtrar ICMP e ainda assim encaminhar o tráfego. Por isso o traceroute é evidência parcial: pode ser bloqueado, incompleto ou assimétrico (a volta pode seguir outro caminho).

Erros comuns
  • "Pinguei o gateway, então a internet funciona." O gateway é o primeiro salto e costuma responder mesmo quando as rotas depois dele falham. Valide por etapas: gateway, rota, caminho e só então DNS e aplicação.
  • Confundir gateway com DNS. Os dois aparecem juntos na configuração, mas o gateway encaminha tráfego e o DNS traduz nomes. Trocar um quando o problema é o outro não resolve.
  • Esquecer a rota de retorno. O pacote chega, mas a resposta não volta porque o destino (ou um roteador no meio) não tem rota para a rede de origem. Valide rotas e políticas nos dois sentidos.
