Exemplo simples

Acessar um site já envolve vários protocolos cooperando. O DNS traduz o nome para um IP. O TCP, na maioria dos casos, estabelece a conexão. O TLS negocia a criptografia e valida o certificado quando o acesso é HTTPS. O HTTP envia uma requisição com método, caminho, headers e às vezes corpo. O servidor responde com status code, headers e conteúdo. 

GET / HTTP/1.1
Host: exemplo.local
User-Agent: navegador
Accept: text/html

Essa pequena mensagem só faz sentido porque cliente e servidor conhecem HTTP. Sem esse contrato, seriam apenas bytes numa conexão.

Se algo falhar, o erro depende da etapa. Se o DNS falhar, o nome não resolve. Se o TCP falhar, a porta pode estar fechada ou bloqueada. Se o TLS falhar, pode haver problema de certificado, versão ou inspeção. Se o HTTP responder com erro, o servidor recebeu e entendeu a mensagem e devolveu, por exemplo, 401 (credencial ausente ou inválida), 403 (identidade reconhecida, mas sem permissão), 404 (recurso não encontrado), 429 (limite de requisições excedido) ou 500 (erro interno do servidor). Cada erro pertence a uma parte diferente da conversa.
