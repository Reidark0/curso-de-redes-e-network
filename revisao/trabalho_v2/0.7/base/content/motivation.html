Motivação

Um computador consegue enviar bytes para outro, mas isso, sozinho, não garante comunicação. O receptor precisa saber onde a mensagem começa e termina, que campos existem, quais valores são permitidos, o que responder, quanto esperar, como tratar erro, quando autenticar e quando encerrar a conversa. Esse conjunto de regras é um protocolo.

Problema real: um sistema interno parou de integrar com uma API depois de uma atualização. O servidor responde ao ping, o DNS resolve, a porta está aberta e o firewall permite o tráfego. Mesmo assim, a chamada falha. O caminho existe; o que quebrou foi a conversa: versão TLS incompatível, cabeçalho HTTP obrigatório ausente, token expirado ou payload JSON fora do formato esperado.

Entender protocolo muda a forma de diagnosticar. Em vez de perguntar só “tem rede?”, você passa a perguntar: a mensagem está no formato certo e na ordem certa? O servidor esperava autenticação antes? Houve negociação de versão? O timeout faz sentido? Um proxy alterou algum cabeçalho?
