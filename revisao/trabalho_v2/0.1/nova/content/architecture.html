Arquitetura

A mesma informação é representada em vários níveis, e cada nível tem quem o interprete e falhas típicas. Esta tabela é um mapa para o troubleshooting:

Nível Exemplo Quem interpreta Falha típica
Sinal físico (camada física) Tensão, luz, rádio Placa de rede, transceptor, rádio Wi-Fi Ruído, atenuação, interferência, cabo ruim
Bit 0 ou 1 Circuitos digitais Erro de leitura ou bit trocado (bit flip)
Byte 8 bits agrupados CPU, sistema operacional, aplicações Encoding incorreto ou byte inesperado
Estrutura de protocolo: enlace, rede e transporte Quadro Ethernet (identifica dispositivos locais), pacote IP (endereçamento lógico e caminho entre redes), segmento TCP (portas, estado e controle de fluxo entre processos) Pilha de rede Campo inválido, checksum, MTU, fragmentação
Dado de aplicação HTTP, JSON, HTML, token, arquivo Aplicação, biblioteca, serviço Formato inválido, codificação errada, parsing inseguro

Esse mapa evita diagnósticos aleatórios. Se os sinais físicos falham, a aplicação nem recebe dados. Se os bytes chegam, mas são interpretados com o encoding errado, o problema parece de aplicação, não de rede. Se o tráfego está criptografado, o analista vê metadados, mas não o conteúdo. Se a captura mostra payload binário, isso não prova ataque: pode ser compressão, formato binário, serialização ou criptografia legítima.
