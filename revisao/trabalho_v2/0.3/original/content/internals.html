6. Funcionamento interno

Vamos acompanhar uma frase simples: Olá. Para um humano, isso é texto. Para uma aplicação, primeiro existem caracteres: O, l e á. No Unicode, cada caractere possui um ponto de código. Em UTF-8, cada ponto de código é transformado em um ou mais bytes. Os caracteres ASCII básicos, como O e l, ocupam 1 byte em UTF-8. O caractere á ocupa 2 bytes: C3 A1 em hexadecimal.

  1. Passo 1: o usuário digita um caractere em uma aplicação.
  2. Passo 2: a aplicação representa esse caractere internamente usando um modelo de texto.
  3. Passo 3: ao salvar ou transmitir, a aplicação escolhe uma codificação, como UTF-8.
  4. Passo 4: a codificação transforma os caracteres em bytes.
  5. Passo 5: os bytes são enviados pela rede dentro de protocolos como HTTP/TCP/IP.
  6. Passo 6: o sistema receptor interpreta os bytes usando a codificação esperada.
  7. Passo 7: se a interpretação estiver errada, o texto exibido ou processado será incorreto.

Base64 funciona de forma diferente. Ele não mapeia caracteres humanos para bytes. Ele pega bytes já existentes e os reagrupa em blocos de 6 bits, usando uma tabela de 64 caracteres. Como 6 bits permitem 64 combinações, é possível representar dados binários usando letras, números e alguns símbolos. O caractere = pode aparecer como preenchimento para indicar alinhamento no final.

Fluxo mental

Texto humano → caracteres → pontos de código Unicode → bytes em UTF-8 → pacotes na rede → bytes recebidos → interpretação → texto novamente.

Bytes binários → Base64 → texto seguro para transporte → decodificação → bytes originais.
