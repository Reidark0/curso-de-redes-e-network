7. Arquitetura

Protocolos aparecem em todas as camadas de uma arquitetura corporativa. Um usuário acessando uma aplicação web pode usar Wi‑Fi, Ethernet, IP, TCP, TLS, HTTP, DNS, autenticação federada, APIs internas, conexão com banco, filas e protocolos de observabilidade. Cada trecho pode estar funcionando ou falhando de maneira diferente.

  • Camadas inferiores: Ethernet, ARP, IP, ICMP, TCP, UDP e roteamento criam conectividade.
  • Camadas de aplicação: DNS, HTTP, SSH, SMTP, APIs e bancos organizam serviços.
  • Camadas de segurança: TLS, Kerberos, SAML, OIDC, OAuth e mTLS criam confiança, identidade e proteção.
  • Camadas de plataforma: Kubernetes, service mesh, ingress, API gateway e observabilidade usam protocolos para automatizar comunicação.
  • Pontos de falha: versão incompatível, porta errada, certificado inválido, token vencido, payload malformado, timeout, proxy alterando header ou WAF bloqueando padrão.

Pensar em protocolo como arquitetura evita um erro comum: culpar a rede por qualquer falha de comunicação. Às vezes a rede entrega os bytes perfeitamente, mas a aplicação rejeita a mensagem porque o contrato não foi cumprido.
