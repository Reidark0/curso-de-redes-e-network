Motivação

Um usuário está conectado por cabo, tem IP, mas não acessa o sistema interno. O primeiro impulso é culpar DNS, firewall, proxy ou a aplicação. Só que, antes de qualquer pacote IP chegar ao roteador, existe uma pergunta local: o host conseguiu montar e entregar um frame Ethernet ao próximo salto correto?

Esta revisão junta o Módulo 3 num raciocínio só. MAC, frame, switch, flooding, broadcast, ARP, VLAN, STP e segurança L2 formam uma cadeia. Quando um elo falha, o sintoma aparece como lentidão, perda de acesso, IP duplicado, gateway inacessível, queda de telefonia, impressora indisponível ou alerta de segurança.

Problema real: se você não entende o caminho do frame até o gateway, trata um problema de ARP como DNS, um problema de VLAN como firewall, um loop de L2 como lentidão genérica e uma porta física exposta como incidente de aplicação.
