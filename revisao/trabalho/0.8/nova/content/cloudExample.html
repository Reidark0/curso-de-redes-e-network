Exemplo em cloud

Em cloud, falhas muito diferentes aparecem para o usuário como "não acessa". A causa pode estar em route table, security group, NSG, DNS privado, endpoint privado, NAT Gateway, load balancer, certificado, WAF, API Gateway, IAM ou política da aplicação. Os nomes parecem os da rede tradicional, mas cada serviço tem regras e evidências próprias.

Exemplo: uma VM em subnet privada precisa chamar uma API externa. Se não há rota para o NAT, o tráfego nem sai. Se o security group nega a saída, a conexão falha. Se o DNS resolve para o endpoint privado errado, o tráfego vai por outro caminho. Se o TLS falha, a porta pode até abrir, mas a aplicação não negocia. Se a API retorna 403, a rede funcionou e a autorização negou.

Regra prática: em cloud, conectividade, exposição e permissão são coisas diferentes. Abrir caminho de rede não concede acesso legítimo; uma negação de IAM não significa que a rede esteja quebrada.
