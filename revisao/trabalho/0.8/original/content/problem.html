3. Problema

O problema central é que uma comunicação real atravessa muitas responsabilidades ao mesmo tempo. Um simples acesso a https://sistema.empresa.local pode envolver Wi-Fi, switch, VLAN, ARP, IP, roteamento, NAT, firewall, DNS, TCP, TLS, HTTP, cookie, token, sessão, banco de dados e autorização.

Se tudo isso for tratado como "a rede", o diagnóstico fica impreciso. Você pode trocar DNS quando a falha é TLS. Pode liberar firewall quando a falha é autorização. Pode culpar o usuário quando o problema é rota. Pode abrir uma porta perigosa quando bastava corrigir um cabeçalho no proxy.

  • Sem camadas: os sintomas se misturam e o troubleshooting vira tentativa.
  • Com camadas: cada hipótese é testada no lugar certo, com evidência adequada.
  • Em segurança: camadas ajudam a separar conectividade, autenticação, autorização e detecção.
  • Em cloud: camadas evitam confundir route table, security group, DNS privado, load balancer e IAM.
