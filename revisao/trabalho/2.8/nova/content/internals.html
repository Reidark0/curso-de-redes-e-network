Funcionamento interno

Escolha primeiro a direção. Bottom-up (da Camada 1 para cima) serve para falhas amplas, como uma filial inteira sem acesso. Top-down (da aplicação para baixo) serve quando há um erro de aplicação claro: HTTP 401/403/500 ou erro de certificado. Começar pela camada "errada" atrasa, mas não invalida o diagnóstico se você seguir o método.

  1. Defina o sintoma: quem falha, de onde, para qual destino, desde quando e com qual mensagem? Relato incompleto leva a investigação para o lugar errado.
  2. Identifique o escopo: um usuário, uma VLAN, uma filial, uma aplicação, um provedor ou todos?
  3. Valide camada por camada (tabela abaixo), interpretando cada resultado: comando sem interpretação gera falsa confiança.
  4. Defina a ação corretiva mínima: altere configuração só com hipótese forte e plano de rollback.
  5. Registre as evidências: comando, horário, origem, destino, resultado, interpretação e hipótese descartada. Isso melhora tickets, handoffs entre times e o pós-incidente.

Num fluxo corporativo (notebook, Wi-Fi, switch, firewall, VPN, proxy, DNS, balanceador, WAF, API gateway, servidor, banco, IAM), uma falha em qualquer etapa gera o mesmo sintoma final; a tabela põe cada evidência no lugar certo.

Quando não seguir o roteiro inteiro: com evidência inequívoca e urgente (ex.: cabo rompido confirmado), corrija. O método também não justifica varreduras sem autorização nem deve atrasar uma mitigação emergencial já definida.
