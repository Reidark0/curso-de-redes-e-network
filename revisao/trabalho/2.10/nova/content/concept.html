Conceito

Definição: revisar o OSI na prática é usar as sete camadas como matriz de raciocínio: mapear um fluxo real em camadas, identificar as PDUs, coletar evidências, separar rede de aplicação e propor ações seguras.

O teste é este: olhar para “cliente acessa aplicação web interna” e descrever o caminho de cima para baixo, com o que pode falhar em cada etapa.

EtapaO que aconteceFalha possível
1. Aplicação (cliente)HTTP, DNS ou API gera os dados (payload) e o contexto: sessão, token.Erro de aplicação, sessão expirada, autorização negada.
2. TransporteEncapsula em TCP ou UDP: portas, handshake, estado e retransmissão.Timeout, reset, porta fechada, bloqueio de firewall stateful.
3. RedeEncapsula em IP e escolhe a rota: IP, gateway, TTL.Rota ausente, gateway incorreto, rota de retorno inexistente.
4. EnlaceEntrega em frames locais: MAC, ARP, VLAN, switch.ARP incorreto, VLAN errada, loop, tabela MAC instável.
5. FísicaCobre, fibra ou rádio transportam os bits.Cabo, interferência, SNR baixo, link flap, erro físico.

No servidor, o caminho se inverte (desencapsulamento). Em cada camada a identidade de “quem fala com quem” muda: MAC na 2, IP na 3, porta na 4, URI e usuário na 7. Por isso IP não é usuário e porta aberta não é autorização.
