Funcionamento interno

Cada passo do envio pode falhar de um jeito diferente, e o cache ARP mostra em qual deles o problema está.

#O que aconteceO que pode falhar
1A aplicação gera tráfego para um IP e a pilha IP escolhe o próximo salto: o próprio destino, se estiver na sub-rede, ou o gateway.Máscara incorreta faz o host procurar ARP para o destino errado ou usar o gateway indevidamente.
2O host consulta o cache ARP pelo IP do próximo salto. Se há entrada válida, monta o frame Ethernet com aquele MAC.Entrada antiga, incompleta ou inconsistente causa falha local ou intermitência.
3Sem entrada, o host envia ARP Request em broadcast para a VLAN; enquanto espera, a entrada aparece como incompleta.VLAN errada, isolamento de Wi-Fi, gateway fora do ar ou broadcast bloqueado impedem a resposta.
4O gateway ou o destino local responde com ARP Reply; o host atualiza o cache e passa a enviar frames unicast.Resposta com MAC inesperado exige correlação com switch, DHCP, NAC e HA.
5A entrada expira depois de um tempo ou é substituída por uma resposta mais nova.Uma resposta nova sobrescreve a antiga sem autenticação: é aí que conflitos e abusos aparecem.

Essa mecânica explica por que limpar o cache ARP às vezes “resolve” o problema por alguns minutos, mas raramente resolve a causa raiz. Se a causa é IP duplicado, VLAN errada, loop, ARP spoofing, gateway em HA mal documentado ou switch instável, a entrada problemática volta.

Erros comuns
  • Confundir ARP com DNS: DNS resolve nome para IP; ARP resolve o IP do próximo salto local (normalmente o gateway) para MAC. Se o gateway não responde, culpar o DNS é olhar para a camada errada.
  • Limpar o cache e encerrar o chamado: limpar é um teste controlado, não a solução. Colete a tabela antes de limpar, ou a evidência some.
  • Tratar MAC como identidade forte: políticas baseadas só em MAC são frágeis, porque o MAC pode ser alterado.
  • Ignorar alta disponibilidade: em HSRP/VRRP o MAC do gateway pode mudar legitimamente. Documente o MAC virtual esperado para não gerar falso positivo.
  • Mexer em firewall ou DNS cedo demais: colete em ordem IP, rota, vizinhos ARP, DNS, porta TCP, TLS e resposta HTTP, e só altere algo depois de provar que a LAN e o gateway funcionam.
