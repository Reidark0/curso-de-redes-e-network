Funcionamento interno

Antes de transmitir qualquer frame, o host toma uma decisão local que depende do próprio IP, da máscara, do IP de destino e da rota padrão.

  1. O host recebe ou possui um endereço IPv4, uma máscara, gateway e DNS.
  2. Ele compara o próprio IP com o IP de destino usando a máscara. Falha típica: máscara incorreta gera decisão errada.
  3. Se o destino estiver na mesma rede, o host descobre o MAC do destino com ARP.
  4. Se o destino estiver em outra rede, o host descobre o MAC do gateway com ARP. Falha típica: sem gateway, nada fora da rede local é alcançado.
  5. O ARP Request/Reply acontece dentro da VLAN local. Falha típica: VLAN errada ou ARP inconsistente impede a entrega local.
  6. O pacote IPv4 mantém IP de origem e IP de destino; o frame Ethernet usa MAC de origem e MAC de destino só para o próximo salto local.
  7. Cada roteador remove o frame local, analisa o pacote IP, consulta a tabela de rotas e cria um novo frame para o próximo enlace. Falha típica: rota ausente ou firewall bloqueando.
Modelo mental: o host não pergunta “qual cabo leva ao destino?”. Ele pergunta primeiro “o destino pertence à minha rede lógica?”. Se sim, usa ARP para o destino. Se não, usa ARP para o gateway. Essa separação evita confundir entrega local, roteamento e resolução de nomes.

Detalhe essencial para troubleshooting: o IP de destino do pacote não muda quando o pacote sai da LAN; o que muda a cada enlace é o frame de Camada 2. Por isso, numa captura local você vê o MAC do gateway como destino Ethernet mesmo quando o IP de destino é um servidor remoto.
