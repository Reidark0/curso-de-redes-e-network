Funcionamento interno

O caminho de um pacote, passo a passo

  1. O host aplica a máscara ao próprio IP e ao IP de destino para saber se o destino está na mesma sub-rede. Falha típica: máscara errada faz o host tratar destino remoto como local, ou local como remoto.
  2. Destino na mesma sub-rede: entrega local, via ARP e Camada 2.
  3. Destino fora da sub-rede: o host consulta as próprias rotas; na maioria dos hosts só existe a default, que envia o pacote ao gateway padrão. Para isso ainda precisa do MAC do gateway, descoberto via ARP. Falha típica: gateway ausente ou errado impede a saída da rede local.
  4. O gateway recebe o frame, remove o encapsulamento de Camada 2 e analisa o pacote IP.
  5. O roteador consulta a tabela de rotas e escolhe a rota mais específica (maior prefixo) que combina com o destino. Falha típica: rota ausente ou errada manda o tráfego para o caminho indevido.
  6. O TTL é decrementado. Se chegar a zero, o pacote é descartado e o roteador pode devolver um ICMP Time Exceeded. Falha típica: loop de roteamento gera perda e respostas de TTL expirado.
  7. O roteador reencapsula o pacote num novo frame de Camada 2 para o próximo salto.
  8. O processo se repete até a rede de destino, ou até o descarte por rota ausente, política ou falha. A resposta faz o caminho inverso e precisa de rota de retorno. Falha típica: a ida funciona, mas a rota ou o firewall de volta falha.

Ponto-chave: os IPs de origem e destino normalmente permanecem de ponta a ponta, enquanto os MACs mudam a cada enlace.

Lendo uma tabela de rotas

Exemplo de saída de ip route num host Linux com IP 192.168.1.50/24:

default via 192.168.1.1 dev eth0
10.0.0.0/8 via 192.168.1.254 dev eth0
192.168.1.0/24 dev eth0 proto kernel scope link src 192.168.1.50

No Windows, o equivalente é route print (a default aparece como destino 0.0.0.0 com máscara 0.0.0.0); no Cisco IOS, show ip route, que mostra rotas conectadas, estáticas e dinâmicas.

Como o traceroute usa o TTL

O traceroute (tracert no Windows) envia sondas com TTL 1, depois 2, depois 3, e assim por diante. Cada roteador em que o TTL chega a zero devolve um ICMP Time Exceeded, e assim aparece como um salto na lista. Um asterisco significa só que aquele salto não respondeu: ele pode filtrar ICMP. Por isso o traceroute é evidência parcial: pode ser bloqueado, incompleto ou assimétrico (a volta pode seguir outro caminho), e em cloud parte do caminho físico é abstraída pelo provedor.

Erros comuns
  • "Pinguei o gateway, então a internet funciona." O gateway é o primeiro salto e costuma responder mesmo quando as rotas externas falham. Valide em etapas: gateway, rota, caminho, DNS, porta e aplicação.
  • Confundir gateway com DNS. Os dois aparecem juntos na configuração, mas o gateway encaminha tráfego e o DNS traduz nomes. Trocar um quando o problema é o outro não resolve.
  • Esquecer a rota de retorno. O teste foca a ida; o pacote chega, mas a resposta não volta. Valide rotas e políticas nos dois sentidos.
  • Tratar o traceroute como mapa absoluto. Ele é evidência parcial, como visto acima.
