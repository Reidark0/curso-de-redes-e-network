Problema

Antes dos switches, a Ethernet usava meio compartilhado ou hubs. O hub repete os bits para todas as portas: não aprende MAC, não olha o destino e deixa todos os hosts no mesmo domínio de colisão, vendo o tráfego uns dos outros. O switch surgiu para a LAN crescer: ele lê o frame, aprende onde está cada MAC e envia o tráfego só pela porta necessária, o que reduz colisões e exposição.

O desafio é entregar frames dentro da LAN de forma eficiente sem exigir configuração manual de cada MAC em cada porta. Por isso o switch precisa de cinco comportamentos:

  • Sem aprendizado automático: cada mudança de porta exigiria configuração manual.
  • Sem forwarding seletivo: tráfego unicast seria desnecessariamente visível para muitos hosts.
  • Sem flooding controlado: um destino desconhecido nunca seria alcançado.
  • Sem aging: a tabela MAC ficaria presa a informações antigas.
  • Sem segmentação por VLAN: aprendizados de redes diferentes se misturariam.

O switch de Camada 2 decide por qual porta um frame sai dentro de uma VLAN. Ele não roteia entre redes (isso exige função de Camada 3) e não substitui firewall, IAM ou criptografia: não sabe se o usuário pode acessar a aplicação.
